# J04 Browse code and commit history

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J04-A:** Browse the pushed commit, file tree, file contents, branches, history, and a bounded diff through stable URLs.
- **J04-B:** Handle binary files, unusual filenames, deleted refs, inaccessible objects, and large output explicitly. Render untrusted content safely and never use shell interpolation for names.
- **J04-C:** If the branch changes, preserve the viewed commit context or explain the refresh. A failed load offers bounded retry without losing navigation.

## Evidence

Supported commit URLs may resolve history reachable from current branches or commit tags, including a release tag whose commit is absent from branches. Internal recovery refs are excluded from this reachability boundary. The tag-only case needs backend proof as well as normal browser history checks.

Browser navigation and keyboard checks, direct API denial, synthetic filename/binary/large diff fixtures. Minimal browsing in M2, complete scope in M4.

Internal navigation must retain shareable commit/path URLs, keyboard activation, browser back/forward
and direct reload. Client navigation must not introduce speculative Git reads or bypass access invalidation.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.
