# J09 Recover an interrupted merge

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J09-A:** Persist merge responsibility, apply the Git change, record the outcome, and expose durable operation state.
- **J09-B:** Inject failure before/after the ref update and before database outcome persistence. Never infer success solely from a job completion flag.
- **J09-C:** Restart and reconcile against actual refs and operation markers. Retry cannot apply twice, discard another writer's update, or leave an eternal spinner.

## Evidence

Deterministic failure injection with real repositories/database, restart, ref and audit assertions.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.

## Rules

Applicable invariants: I04, I05, I06. See [quality rules](../../QUALITY.md).

## Completion

All criteria need current evidence against the intended build and requirement revision. Record limitations and open failures in the ledger. Product/reviewer acceptance follows QUALITY.md.
