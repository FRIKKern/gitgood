# J15 Upgrade and reject unhealthy releases

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J15-A:** Stage compatible artifacts, run controlled migrations, verify readiness and functionality, then activate the intended release.
- **J15-B:** An unhealthy candidate never replaces a working compatible release. Distinguish code rollback from schema rollback; document maintenance where required.
- **J15-C:** Failure exposes the stage and supported retry, rollback, or forward-repair path. Verify routing and running versions after recovery.

## Evidence

Bad build fixture, migration failure, compatibility matrix, activation/recovery and public endpoint probes.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.

## Rules

Applicable invariants: I05, I06, I09. See [quality rules](../../QUALITY.md).

## Completion

All criteria need current evidence against the intended build and requirement revision. Record limitations and open failures in the ledger. Product/reviewer acceptance follows QUALITY.md.
