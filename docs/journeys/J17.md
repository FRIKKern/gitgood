# J17 Export archive and remove

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J17-A:** Export code and collaboration records in documented formats; archive an installation with clear retention and removal semantics.
- **J17-B:** Explain what will be retained/deleted. Prevent unauthorized removal and orphaned provider resources. Scope destructive acceptance to disposable fixtures.
- **J17-C:** Retry without deleting unrelated resources; retained archive remains usable under documented access and key policy.

## Evidence

Disposable installation export/restore, resource inventory, credential cleanup, retention and repeated-operation checks.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.

## Rules

Applicable invariants: I01, I08, I10. See [quality rules](../../QUALITY.md).

## Completion

All criteria need current evidence against the intended build and requirement revision. Record limitations and open failures in the ledger. Agents evaluate current evidence under QUALITY.md and AUTONOMY.md and advance when criteria pass; no human acceptance is required.
