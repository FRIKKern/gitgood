# J10 Connect tasks and specifications

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J10-A:** Link a supported Barkpark task/specification to a Gitgood change and navigate both directions with enough context.
- **J10-B:** Access is enforced independently at both owners. No mirror silently becomes the authority. Missing or deleted linked records are explained.
- **J10-C:** Barkpark outage shows unavailable state and preserves existing forge access; retries do not duplicate links or claim external writes succeeded.

## Evidence

Actual supported Barkpark API, two identities, backend outage, deleted link and attribution checks.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.
