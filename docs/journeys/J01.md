# J01 Create a private repository

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J01-A:** An authenticated team member creates a repository and receives its canonical URL. Reloading preserves the repository and its owner.
- **J01-B:** A second user outside the team cannot discover the repository through lists/search/events or fetch its content. Duplicate names and expired sessions return actionable errors without duplicate creation.
- **J01-C:** Retry after a lost response resolves to the original operation; failure does not leave an inaccessible billed or stored orphan.

## Evidence

Browser plus API checks with two identities; verify actual database ownership and repository existence.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.

## Rules

Applicable invariants: I01, I02, I08. See [quality rules](../../QUALITY.md).

## Completion

All criteria need current evidence against the intended build and requirement revision. Record limitations and open failures in the ledger. Agents evaluate current evidence under QUALITY.md and AUTONOMY.md and advance when criteria pass; no human acceptance is required.
