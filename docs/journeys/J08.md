# J08 Merge under current policy

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J08-A:** Validate actor, current branch policy, source/target state, approvals, and required checks; apply one documented merge strategy and record exact outcome.
- **J08-B:** Source/target changes, revoked membership, failed checks, conflicts, and concurrent attempts cannot bypass validation. Define authorized override behavior and audit it if supported.
- **J08-C:** If validation becomes stale, re-evaluate or refuse explicitly. No misleading success is returned for an unrecorded or unapplied action.

## Evidence

Concurrent push/merge tests, permission/policy mutation tests, expected-ref checks, resulting history and audit comparison.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.

## Rules

Applicable invariants: I02, I03, I04, I08. See [quality rules](../../QUALITY.md).

## Completion

All criteria need current evidence against the intended build and requirement revision. Record limitations and open failures in the ledger. Agents evaluate current evidence under QUALITY.md and AUTONOMY.md and advance when criteria pass; no human acceptance is required.
