# J16 Restore onto a replacement host

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J16-A:** Create a consistent backup of every authoritative store and restore on another host, including required configuration and secret material.
- **J16-B:** Reject incomplete/corrupt/incompatible backups; do not declare readiness from a database import alone.
- **J16-C:** Verify expected refs/history, collaboration records, denied users, asset access, authorized clone and new push. Measure data loss and recovery time.

## Evidence

Full restore exercise, checksums/versions, permission assertions, real Git operations, timing against agreed targets.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.

## Rules

Applicable invariants: I01, I06, I10. See [quality rules](../../QUALITY.md).

## Completion

All criteria need current evidence against the intended build and requirement revision. Record limitations and open failures in the ledger. Agents evaluate current evidence under QUALITY.md and AUTONOMY.md and advance when criteria pass; no human acceptance is required.
