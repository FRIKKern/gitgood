# J06 Review and update a pull request

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J06-A:** Open a same-repository pull request, comment on exact lines, submit a review, push an update, and retain understandable original context.
- **J06-B:** Unauthorized reviewers are refused. Define approval invalidation after source/target changes. Comments whose lines move retain their original commit and diff context.
- **J06-C:** Preserve unsent browser comments across the documented connection-failure path. Retry submitted comments without duplication.

## Evidence

New pull and review identities use persisted opaque UUIDs, including stable review anchors. Existing numeric pull links remain authorized repository-scoped aliases. Upgrade/restart must preserve both attribution and new UUID links; raw internal record sequences must not become discovery counts.

Two-browser review, real pushes, old/new diff association, keyboard/focus and access tests.

Opening a pull request from its repository list must retain its canonical URL and support keyboard
activation without a full document reload. Direct entry, reload and permission invalidation still apply.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.

## Rules

Applicable invariants: I01, I03, I08. See [quality rules](../../QUALITY.md).

## Completion

All criteria need current evidence against the intended build and requirement revision. Record limitations and open failures in the ledger. Agents evaluate current evidence under QUALITY.md and AUTONOMY.md and advance when criteria pass; no human acceptance is required.
