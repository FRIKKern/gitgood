# J12 Publish a basic release

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J12-A:** Create a release tied to an identified tag/commit, attach assets, and publish reviewed notes showing actual included changes.
- **J12-B:** Reject unauthorized publication and invalid artifact identity; do not present main-branch work or a pending deployment as released.
- **J12-C:** Retry asset/publication steps without duplication. Correct or withdraw mistaken claims with retained traceability.

## Evidence

The supported first-release contract is a private draft/published/withdrawn record pinned to an existing lightweight or annotated commit tag. It includes a server-derived range of up to 200 actual commits and plain notes. Publication acknowledges the current notes digest/revision and requires unchanged tag identity and at least one ready immutable asset. Assets are 1 byte–16 MiB, up to eight active assets per release, stored transactionally in Postgres and served only as authorized published attachments. Corrections require reasons and retain old attributed snapshots; withdrawal is terminal and stops new downloads while preserving the recorded claim. No deployment state or main-branch movement implies publication. See [implementation](../implementation/releases.md) and [decision](../decisions/0007-basic-private-releases.md).

Prove partial upload/reload resume and lost draft/upload/publication replies, actual version-versus-main changes, private exact-byte downloads, current authority, stale/concurrent revisions, immutable tag/asset identity, corrections/withdrawal, worker/whole-VM interruption and copied-artifact restart persistence. Artifact checks establish declared byte identity; they do not attest how arbitrary uploads were built.

API/browser release workflow, asset access tests, idempotency, version-to-commit and notes reconciliation.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.

## Rules

Applicable invariants: I01, I08, I09. See [quality rules](../../QUALITY.md).

## Completion

All criteria need current evidence against the intended build and requirement revision. Record limitations and open failures in the ledger. Agents evaluate current evidence under QUALITY.md and AUTONOMY.md and advance when criteria pass; no human acceptance is required.
