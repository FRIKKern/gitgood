# J05 Import a supported repository

## Preconditions

Use synthetic fixtures and isolated stores. Record code/spec revisions, runtime versions, actual actors, and the relevant configuration. Milestone membership is defined in catalog.json.

## Acceptance criteria

- **J05-A:** Import an allowed source and compare expected refs and history with the original. Record source and operation outcome.
- **J05-B:** Validate source access and network boundaries. Explain unsupported LFS/submodule/other forge metadata rather than implying a lossless import.
- **J05-C:** Interrupted or repeated imports do not duplicate repositories or expose credentials; retain or clean partial work by a documented policy.

## Initial supported-source contract

The first allowed source is an uploaded full SHA-1 Git version-2 bundle including main, with at most 64 unique branches/tags and 32 MiB. The repository creator with a current session/write role may initialize an empty managed target. Source URLs, server paths, prerequisites, filtered/incremental/version-3 bundles and other refs are rejected. See [the import decision](../decisions/0006-offline-bundle-import.md) and [implementation/reproduction](../implementation/import.md).

J05-A requires exact branch/tag object IDs and historical commit-chain comparisons, durable source digest/size and attributed outcome. J05-B requires backend authorization, denial of URL/path sources and malformed/unsupported bundles, bounded intake and explicit external-content/forge-metadata limitations. J05-C requires lost-response replay, partial-source retry, competing-write refusal, worker/VM interruption before and after atomic publication, visible uncertainty, bounded automatic attempts and documented staging cleanup.

## Evidence artifacts

Fixture source repository, ref/object comparison, unsupported feature report, timeout and retry test.

A result must identify which of the criteria above it establishes. Store manifest references; keep private artifacts access-controlled. Unimplemented or unmeasured behavior stays unverified.

## Rules

Applicable invariants: I01, I04, I06. See [quality rules](../../QUALITY.md).

## Completion

All criteria need current evidence against the intended build and requirement revision. Record limitations and open failures in the ledger. Agents evaluate current evidence under QUALITY.md and AUTONOMY.md and advance when criteria pass; no human acceptance is required.
