# D05 Git and database recovery
Status: initial marker protocol accepted, 8 October 2026. Owner: Codex under delegated project authority.

Responsibility commits independently before the Git change. One Git ref transaction verifies the source,
conditionally advances main and creates an operation marker. Recovery checks actual marker and target ancestry.
A durable result records exact revisions, actor, policy and check/review snapshots. A replay returns the same operation.
Inconsistent or unavailable evidence remains uncertain and blocks writes.

Nine isolated real-database scenarios exercise concurrent requests, actor/reviewer/check/policy gates, divergent history,
source/target interference and termination before/after Git refs and before outcome persistence, followed by application restart.
Whole VM exit and fresh-process recovery were additionally exercised at all three boundaries.
Strict fsck and ref/audit comparisons are part of the verification.

Run [the recovery commands](../implementation/collaboration.md). Local artifacts remain private under ignored .gitgood/verification;
CI retains candidate artifacts. These experiments use Elixir 1.20.4 / OTP 29.1.1, Postgres 18.4 and standard Git on Windows.
Linux CI is required for integration. Storage power loss, rolling upgrades, distributed failover and uncertain-store repair remain
unverified. Quiesce old processes before introducing new operation semantics.
