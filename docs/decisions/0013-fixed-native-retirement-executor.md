# Fixed native retirement execution

Status: accepted; actual scoped installed CLI execution passed, required integration CI pending.

The five installed retirement stages have actual scoped proof, but callers still
sequence their libraries through private fixture drivers. Codex primary agent
chooses one fixed executor and a native operator command over those same typed
controllers. This advances J17 without introducing arbitrary commands, callback
actions, provider cleanup, or a second authoritative operation record.

The executor reads five fixed private files from one independently identified
plan directory: `plan.json`, `resources.json`, `retention.json`, `checkpoint.json`
and `full-restoration-plan.json`. An independently supplied canonical plan SHA256
binds all other input digests. Strict existing resource/restoration parsers apply;
files and their private parent identities are observed again around each stage.
Plan files/history/probe credentials/recovery materials must stay outside the
original three stores and the recovery target. Secrets remain in private files,
never command arguments, status output or ordinary evidence.

Execution requires the installation owner already running inside its enrolled
driver group through the OS service/delegation boundary. The executor cannot
allocate or adopt kernel groups, databases, provider resources or foreign roots.
Initial enrollment and independent target allocation remain separate work. It
holds the existing installation lifecycle lock and uses the retirement journal
as the sole stage authority. Archive/key/code identities and writer exclusion
are reobserved before source deletion; original configuration is durably retained
before database removal, and cannot be reconstructed from unbound credentials.

Pending execution runs the fixed stages in order. Failed or dead-owner stages
must first observe their actual bound state. Quiescence can repeat exact scoped
stops without claiming that no earlier stop occurred. Archive retry must prove
unchanged original contents and stop its sealed target groups. It observes an
already restored target; an empty target may be imported only through the fixed
empty-database helper. Partial populated/invalid targets remain preserved and
refuse. Database/store retries use actual exact absence or matching remaining
entries before applying/unapplied acknowledgement; shared roles and replacements
remain preserved. Final retry uses the already proved retained-usability
controller. Failed actions retain responsibility and a fixed failure code.

A terminal same-intent invocation reports previously recorded completion
without reopening the journal or making a fresh usability claim. `status` stays
a read-only metadata observation. Changing intent, input bindings or relevant
resource identities refuses; an unavailable archive/database is not silently
treated as removal or recovery success. No automatic cancellation clears a
retirement fence, and no completed local record implies host deallocation.

Verification must include actual CLI-driven installed execution, competing owner
and changed-input refusal, lost-owner responsibility, destructive-stage
reconciliation and a same-intent terminal repeat that preserves retained records.
Unit fixtures alone cannot establish these cases. The acting producer/verifier,
exact operator/application identity, failures and private artifact digests remain
explicit. Managed Cloud, enrollment, cancellation and release acceptance stay
separate dependent work.

Three actual CLI cases passed against the same25 independently hashed operator
files and clean application artifact: continuation after acknowledged archive
verification, recovery after exact-birth owner loss before the first import,
and all five stages from absent retirement journal/fence. Each passed five CLI
checks and two repeated terminal calls, with one import and all nine groups
empty. Terminal calls preserved109/100/94 history files respectively. Their
126/122/117-file archives passed checksum and credential-exclusion readback.
The ordinary case exercised quiescence, archive function, exact database/store
removal and final retained function through the actual command. Initial
enrollment/export/checkpoint and independent target/plan allocation used fixed
fixture libraries. These same-host/kernel observations establish the scoped
executor behavior; they do not establish managed Cloud or complete release.
