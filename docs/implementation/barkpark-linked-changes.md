## Opaque landing implementation

GET /api/changes/:uuid resolves a pull request only within the current reader's locked session/membership snapshot and repository credential scope. It accepts the public UUID rather than an integer ID. Foreign and nonexistent identities return the same 404; unauthenticated callers receive only sign-in-required. The normal before-send authorization guard still redacts a response if native access changes.

The browser /changes/:uuid landing page shows no repository or title before current native authorization. Successful resolution opens the native pull-request route. Sign-in preserves only a validated UUID return target; arbitrary URLs or paths cannot become redirect destinations. The query uses the native access boundary and an abort signal, so old-account responses cannot activate a former destination.

The focused database/API fixtures cover permitted readers, malformed/unknown/foreign IDs, repository-scoped credentials, revoked sessions and removed memberships. Actual Git-client/browser tests create a real change, follow its opaque address, complete sign-in, compare denied and missing results, and hold an old lookup through a shared-cookie account switch. These prerequisites do not implement external link records, a source mutation journal or complete J10 acceptance.
