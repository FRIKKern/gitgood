# Barkpark connection boundary

The first implementation is a bounded native-backend HTTP adapter and an exercised source contract. Backend per-account encrypted connection storage is described in [private accounts](barkpark-accounts.md). Linked-change UI, reverse-link publication and complete J10 acceptance remain pending. The live implementation ledger is still unconfigured.

Gitgood.BarkparkHTTP reads only the installation-configured GITGOOD_BARKPARK_ORIGIN. It refuses origin credentials, non-root origin paths, queries/fragments and absolute/host-bearing request paths. Production configuration requires HTTPS. Peer and hostname checks use Python's normal TLS context; redirects and compressed responses are refused. No proxy environment or application secrets are inherited by the child process. The selected bearer travels through stdin rather than arguments or browser code.

The Python utility performs I/O only. Elixir owns request selection and will own authorization and durable link operations. The utility accepts GET/POST, limits request input to 2 MiB, mutation JSON and response bodies to 1 MiB, and uses two-second socket timeouts under a five-second supervised subprocess deadline. JSON output is explicitly UTF-8 on Windows and Linux. Unsupported/malformed, oversized and unavailable responses fail closed. Actual HTTP denial/missing/unavailable statuses are retained for the owning context to interpret; the adapter alone cannot establish that a record was deleted.

Four external request workers are separate from the four Git command workers. A real loopback wire fixture fills the external workers, observes refusal of a fifth request, and runs an ordinary native Git command before releasing the held responses. The fixture also exercises source statuses, UTF-8 mutation/idempotency headers, redirects without a second request, declared/unbounded response limits, exact-limit success, malformed/encoded responses, and refusal of an untrusted TLS peer. These checks do not claim forge-native/external atomic authorization.

An owned private source experiment uses two separately minted, seven-day service credentials confined to separate verification workspaces. Scoped native HTTPS GET/POST succeeds for the selected credential; a foreign credential is refused. Repeating a supported source idempotency key returns the original transaction and preserves the existing task identity/revision. Private receipts record each deployed build rather than assuming the local source revision matches a changing remote service. Fixture credentials are protected with Windows encryption outside tracked source.

See the [link decision](../decisions/0009-supported-barkpark-links.md) for independent permissions, source ownership, reverse-navigation and retry constraints. No Cloud deployment or journey completion is inferred from these experiments.
