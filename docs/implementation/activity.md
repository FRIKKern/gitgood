# Private discovery implementation

J13 now includes native permission-filtered search/activity and a shared browser access boundary. Private local proof exists on Windows and independent Linux; remote integration and full release acceptance remain pending.

Native reads search permitted repositories, pull requests and releases. Activity reads their actual creation/review/release records and durable push/merge/import operations. The backend joins current membership before applying matching, pagination or snippets; scoped session credentials restrict all reads to their repository. Unknown input is refused, wildcard characters are literal and UTF-8 queries are bounded to 256 bytes. Each page contains at most 50 records, with no global count or sequence cursor. Authenticated encrypted cursors bind the current actor/credential/access context, filter and 15-minute expiry.

Refresh replaces a full recent snapshot. The visible activity window refreshes every five seconds while foregrounded. There is no sequence-based subscription or commit-order assumption. Older pages are live views; concurrent changes can move records between them. A changed context or expired/foreign cursor requires restarting the view. Source errors hide previous results and offer retry; an actual database lock/statement-timeout test distinguishes unavailable source from a valid empty result.

Pull requests and review/release audit events have persisted opaque UUIDs. Numeric pull URLs remain scoped compatibility aliases. Review links explicitly load their selected event alongside the latest 500 entries, including older retained events. Durable operation pages use their existing UUIDs; release links use their persisted UUID. Backfill preserves existing records, and migrations refuse to discard published identities or membership audit records.

Access.with_session validates the actual current credential, expiry and actor, and holds credential/membership share locks throughout its read callback. Role changes and credential revocation serialize with those reads. Private HTTP responses carry an opaque current-access digest; a final backend check redacts a changed/revoked response, including private attachment name/checksum/length headers. Supplied stale context is rejected before disclosure.

All browser routes share one access generation. A changed credential/account/role, sign-out, inactive tab or unavailable access check removes private query results and unmounts transient tokens, files and live drafts. Responses from an older generation cannot refill caches or start an asset download. Foreground polling detects changes within the check interval and request latency; it makes no instantaneous erasure claim. Reconnect and tab activation require a new session check. Cross-tab messages request fresh authorization rather than transmitting private data.

Revision-bound comment drafts survive reload only when the actual session verifies the same opaque access marker. A different context clears them. The marker grants no access and contains no credential. Unknown-outcome JSON retries retain at most 128 opaque request fingerprints/nonces in memory for one day, keyed with a non-extractable ephemeral HMAC key; a different verified actor discards them. Payloads and tokens are not copied into that recovery map. Reload loses that ephemeral map, so callers must reconcile durable operations when their own recovery records do not retain a key.

Owners can grant/change/remove existing installation accounts through the team membership UI/API. A serialized per-team database lock protects concurrent changes and the final owner. Expected roles prevent stale writes; idempotency keys converge on one retained audit UUID. Current owner authorization is required even for retries. A self-removing owner can receive a changed-access response after the committed change; the refreshed session and remaining owner's audit resolve that outcome. There is no public signup or invitation delivery.
